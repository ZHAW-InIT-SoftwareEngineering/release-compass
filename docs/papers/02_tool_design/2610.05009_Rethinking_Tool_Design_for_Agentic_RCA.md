# Rethinking Tool Design for Agentic RCA: A Controlled Empirical Study

- **Authors:** Yu Luo, Rongchen Gao, Zhenhui Zhou, Changchang Liu, Yuliang You, Yongqian Sun, Shenglin Zhang, Qiuai Fu, Shijie Wang, and Dan Pei
- **Version:** arXiv:2610.05009v1 (4 October 2026)
- **Field:** Software Engineering (cs.SE)
- **Paper:** [arXiv abstract and PDF](https://arxiv.org/abs/2610.05009)

## Summary

The authors study how the abstraction and composition of tools affect LLM-based root cause analysis in microservice systems. They compare a Python execution baseline (L0) with structured tools for metric access (L1), evidence analysis (L2), and diagnosis (L3), using 375 failure cases across three systems and multiple Qwen models.

Tool configurations affect root-cause localization and failure-type identification differently. Higher-level tools can reduce analysis time, while combining tool levels may improve failure-type identification but reduce localization accuracy. The best configuration also varies by model and target system. The paper recommends choosing tools according to the model, diagnostic objective, and environment.

## Relevance to Release Compass

The study offers empirical context for designing agent tools: it highlights the tradeoffs between exposing raw evidence, providing analysis operations, and returning diagnosis-oriented results. Its RCA domain differs from release assessment, so the findings are useful as design considerations rather than direct performance evidence for this project.
